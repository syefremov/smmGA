# Фаза 1: аудит основной Windows-машины

Дата проверки: 2 сентября 2026 года.

## Итог

Репозиторная и runtime-часть фазы 1 готова. Системная часть завершена не полностью из-за legacy Docker Desktop 3.2.1. Удаление старой Docker-инсталляции не выполнялось, потому что обнаружен отдельный WSL-диск, который может содержать пользовательские images/volumes.

Фаза 1 остаётся в статусе `in progress` до восстановления рабочего Docker Engine/Compose и повторной успешной диагностики.

- Git обновлён до 2.55;
- Node.js обновлён до 24.19.0;
- pnpm 11.19.0 активирован через Corepack в пользовательском PATH;
- WSL обновлён до современной Store/MSI-ветки;
- создана локальная `.venv`, исключённая из Git;
- Docker Desktop 4.89.0 скачан и проверен по официальному SHA-256, но не установлен из-за несовместимости legacy installation layout.

Сервер, SSH-настройки сервера, внешние аккаунты и реальные секреты не изменялись.

## Docker-блокер

Новый установщик Docker Desktop останавливается на проверке безопасности ACL:

```text
Path contains symlink: C:\ProgramData\DockerDesktop\version-bin\docker
```

Проверено, что это symlink старой Docker Desktop 3.2.1 на legacy CLI. Остановка старых процессов, точечное удаление symlink и перенос служебного каталога не помогли: legacy installer/service layout восстанавливает ссылку до проверки нового установщика.

Обнаружен WSL-диск `docker-desktop-data` размером около 2.89 GB, последний раз изменявшийся в 2021 году. Он может содержать старые images, containers или volumes. Поэтому не выполнялись:

- Docker Desktop uninstall;
- `wsl --unregister docker-desktop-data`;
- удаление Docker VHDX;
- factory reset или очистка Docker data.

Эти операции могут уничтожить данные и требуют отдельного решения владельца.

## Рекомендуемое безопасное продолжение

1. Освободить место до рекомендуемых 30 GB.
2. Определить, нужны ли старые Docker-данные 2021 года.
3. Если данные могут быть нужны, экспортировать `docker-desktop-data` на другой диск или внешний носитель и проверить, что backup читается.
4. После backup удалить legacy Docker Desktop штатным uninstall, не удаляя backup.
5. Установить Docker Desktop 4.89.0 с WSL2 backend.
6. Запустить Docker Desktop и проверить Engine/Compose через `pnpm doctor`.
7. Выполнить повторный `pnpm bootstrap` и `pnpm check`.

До решения пункта 2 репозиторная работа может продолжаться, но фаза 2 не должна считаться закрытой и локальные Docker integration tests запускать нельзя.
